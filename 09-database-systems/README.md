# 09 数据库系统

[← 回到路线](../README.md)

关系模型、SQL、B+ 树索引、事务、MVCC、存储引擎、KV 存储。SQL 会写只是入口，慢查询和「读到了别人没提交的数据」都在后面。完整子类见 [知识地图](../knowledge-map.md)。

## 为什么要学

全栈避不开数据库。索引加错，接口超时；隔离级别没想清楚，用户会看到算到一半的订单。ORM 把 SQL 藏起来之后，更需要自己知道底下在做什么，否则生成的语句只能靠感觉改。

## 建议顺序

1. **关系模型** — 表、行、键、外键。关系是集合，不是「Excel 再加一点约束」。先能把一段业务说成实体和它们之间的关系。
2. **SQL** — 查询、连接、聚合、分组。先写对，再谈快。能用手画出一次连接的结果。
3. **B+ 树索引** — 大多数索引是一棵叶子相连的 B+ 树。它让等值和范围查找少读盘。最左前缀、为什么 `LIKE '%x'` 用不上普通索引，放在这一节。
4. **事务** — 一组操作要么都留下，要么都不留。ACID 里先抓住原子性和隔离。隔离级别是「允许看见别人多少中间状态」的刻度。
5. **MVCC** — 给行留多个版本，读的人看自己开始时的快照，写的人另写一版。读不阻塞写，靠的是这个。不同数据库的实现细节不一样，先掌握这个动机。
6. **存储引擎** — 页、缓冲池、预写日志（WAL）。提交时先把日志落盘，崩溃后可以重做。这是「提交了就还在」的来处。
7. **KV 存储** — 键值对。LSM 树用顺序写换随机写。和 B+ 树对照：一个更适合读多、范围查，一个更适合写多。Redis 这类内存 KV 是另一条线，先分清「持久化引擎」和「缓存」。
