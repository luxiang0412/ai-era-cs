# 06 系统级编程

[← 回到路线](../README.md)

编译和链接、进程的内存布局、异常、虚拟内存、I/O 多路复用。上一层是机器怎么造出来，这一层是一个 C 程序（以及跑在类似模型上的语言）怎么在那台机器上活着。完整子类见 [知识地图](../knowledge-map.md)。

## 为什么要学

前端同学写 JS 时觉得内存是自动的。一碰到 Node 原生扩展、WASM、崩溃栈、容器里的 OOM，又回到这一层：代码在哪，栈在哪，堆在哪，缺页是谁在处理。CS:APP 就是按这个顺序写的。

## 建议顺序

1. **编译链接** — 预处理、编译、汇编、链接。目标文件里有代码和符号，链接器把多个文件和库拼成一个可执行文件。`undefined reference` 是这一步的失败。
2. **内存布局** — 一个进程里：代码、只读数据、全局区、堆向上长、栈向下长。局部变量在栈上，`malloc` / `new` 在堆上。
3. **异常** — 控制流突然转到别处。中断、陷阱、故障，都是异常的不同来源。系统调用是程序主动陷入内核。
4. **虚拟内存** — 每个进程看见自己的一片连续地址，底下是页表在翻译。缺页、TLB、写时复制，先知道它们各自在解决什么。和 [07 的内存管理](../07-operating-systems/README.md) 是同一件事的两面：这里从程序看，那里从内核看。
5. **I/O 多路复用** — 一个线程同时等很多个文件描述符：select、poll、epoll、kqueue、io_uring。Node 的事件循环、Nginx、Redis 都建在这上面。先用 `strace` 看一次 Node 服务在 `epoll_wait` 上睡着。

## 书和课

- 《深入理解计算机系统》Randal Bryant, David O'Hallaron，[csapp.cs.cmu.edu](https://csapp.cs.cmu.edu/)
- [CMU 15-213](https://www.cs.cmu.edu/~213/)

建议对着书里的小实验跑，不要只读。让 AI 写一个打印局部变量和堆地址的小程序，再故意越界，看它什么时候才爆。能读一段崩溃栈，指出哪一帧是自己的函数，这一节就没白看。
