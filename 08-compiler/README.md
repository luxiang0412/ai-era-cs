# 08 编译器

[← 回到路线](../README.md)

词法、语法分析、抽象语法树、解释器、类型、代码生成。做一个小语言，是为了看清「源码变成行为」的中间那些结构。

## 为什么要学

写前端的人已经在用编译器：打包器、TypeScript、模板引擎、ESLint。报错「在解析这里失败」或者「类型推不出来」，如果见过词法和类型检查长什么样，就知道该看哪一层。自己写过一个能跑的表达式解释器之后，这些工具不再是黑盒。

## 建议顺序

1. **词法** — 字符流变成记号：数字、名字、运算符。空格和注释在这里丢掉。
2. **语法分析** — 记号流变成树。先写递归下降，对着文法看每一条规则对应哪个函数。优先级和结合性是这一步要处理的事。
3. **AST** — 抽象语法树丢掉了括号这类只为解析服务的东西，留下结构。后面所有步骤都在走这棵树。
4. **解释器** — 遍历树，直接执行。环境（变量表）一层层套起来，函数调用就是压进一个新环境。
5. **类型** — 在跑之前判断这棵树合不合法。先做简单的检查：数字不能加字符串。类型推导可以后做。
6. **代码生成** — 把树变成另一套指令：字节码或者很简单的汇编。虚拟机一个循环取指令执行。和 [03 的指令集](../03-architecture/README.md) 在这里碰上。

## 书和课

- [Crafting Interpreters](https://craftinginterpreters.com/)，Robert Nystrom。前半用 Java 写树遍历解释器，后半用 C 写字节码虚拟机。先做前半就够建立图像
- 中文可以对照读，但例子以书上的为准，不要同时再开一门完全不同的编译原理课

这一节的 demo 就是书上的计算器，再加上一个能把 AST 画出来的页面。单步执行时高亮当前节点。能讲清「解析失败」和「运行时除以零」不是同一层的错，就算入门了。
