# 题目

[← 回到路线](../README.md)

写给以后的自己。语气像在给同事讲：句子短，例子具体，少口号。成品对照 [`08-computer-networks/tcp/`](../08-computer-networks/tcp/README.md)。

每个子主题按 [知识地图](../knowledge-map.md) 里的七个学习单元往下长。不必一次写满，但缺哪一块要心里有数：

| 学习单元 | 落在哪里 |
| --- | --- |
| Concept 概念与原理 | 本文件的一句话版、生活类比版、深入细节版 |
| Visualization 可交互动画 | `viz/` |
| Demo 最小实现 | `demo/` |
| Lab 动手实验与故障注入 | 本文件的「动手实验」 |
| Real World 真实系统 | 本文件的「真实世界」 |
| Assessment 自测与验收 | 本文件的「自测题」 |
| Resources 资料 | 本文件的「资料」 |

## 一句话版

一两句，只留核心机制。读完能向别人复述。

## 生活类比版

一个画面就够。类比在哪里失真，用一句话点破，避免以后拿错模型。

## 深入细节版

### 从小处写起

按「先看到现象，再讲机制，再讲它会怎么坏」来排。术语第一次出现时用大白话垫一句。

### 再往下

这一层可以出现真实的名字、数量级、和相邻主题的边界。例如流量控制和拥塞控制不要写在同一段里装成一件事。

## 动手实验

写出能复制的命令，以及看的时候眼睛该盯哪里。至少留一个「故意改坏」的入口：改哪个参数，现象会变成什么样。

## 真实世界

到真实系统里找它：一段源码、一份日志、一次抓包、一个线上事故。写清楚去哪里看、看到的东西对应上面哪一段。

## 自测题

三到六题。先让自己讲，再翻答案。答案可以折在 `<details>` 里。

## 资料

教材的哪一章、哪一节课、哪篇论文、哪份官方文档。写清楚读到哪里为止。
