# 08 计算机网络

[← 回到路线](../README.md)

分层、IP、TCP/UDP、DNS、HTTP、TLS、SSH、WebSocket、QUIC。日常写的接口几乎都在这一层上面。完整子类见 [知识地图](../knowledge-map.md)。

## 为什么要学

请求慢、连接被重置、证书报错、本地可以线上不行，排错就是在分层里定位：是 DNS、是 TCP 没连上、是 TLS 握手失败，还是 HTTP 状态码本身。工具（浏览器网络面板、`curl -v`、tcpdump）只有在你知道每一行属于哪一层时才有用。

这一仓库的成品样例是 [TCP](tcp/README.md)。其他子主题按同样的格式往下长：三层讲解、一个小 demo、一段能单步的动画。

## 建议顺序

1. **分层模型** — 每一层只解决一件事，并且只跟相邻层说话。先用四层（链路、网际、传输、应用）够用，OSI 七层当作对照表，不要背。
2. **IP** — 地址和转发。路由器只看目的 IP，把包交给下一跳。它不保证送到。子网和私网地址先会认。
3. **TCP / UDP** — 端口把包交给哪一个进程。UDP 几乎是「带端口的 IP」。TCP 在这之上做可靠的字节流。从 [TCP 这一节](tcp/README.md) 做起，里面有 demo 和动画。
4. **DNS** — 名字换成地址。递归解析、缓存、TTL。先会读一次 `dig` 的输出。
5. **HTTP/1、HTTP/2、HTTP/3** — HTTP/1.1 是文本请求和响应。HTTP/2 在一条连接上多路复用。HTTP/3 换到 QUIC 上，躲开 TCP 的队头阻塞。先把 1.1 的请求行、头、体看熟。
6. **TLS** — 在已经建立的传输上做加密和身份。证书证明「这个公钥属于这个名字」。和 TCP 握手不是同一件事。
7. **SSH** — 远程的加密壳。密钥登录、端口转发。它也是理解「安全壳 + 通道」的一个具体例子。
8. **WebSocket** — 在 HTTP 上升级出一条双向通道。适合服务器要主动推的时候。它不是「更快的 HTTP」。
9. **QUIC** — 在 UDP 上自己做连接、可靠和多路复用，并且把加密算进握手。HTTP/3 跑在上面。看的时候对照 TCP 那一节：它想去掉哪几个代价。

## 书和课

- Kurose, Ross《计算机网络：自顶向下方法》。从应用层往下，和写业务的顺序一致
- [Stanford CS144](https://cs144.github.io/)，自己实现一个 IP/TCP 栈。做之前先把本仓库的 TCP demo 跑熟，那个是缩小版

抓包实验写在 [TCP 的动手部分](tcp/README.md)。DNS 和 HTTP 之后也可以各做一页动画：一次解析经过了哪些缓存，一个 HTTP/2 连接上的多个流怎么被一个 TCP 丢包一起拖住。
