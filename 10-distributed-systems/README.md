# 10 分布式系统

[← 回到路线](../README.md)

CAP、一致性、复制、分片、Raft、分布式事务。一台机器不够用，或者不能挂，才会走到这里。不要为了架构图先拆。完整子类见 [知识地图](../knowledge-map.md)。

## 为什么要学

线上的数据库主从、缓存和库不一致、任务重复执行，都是这一层的现象。CAP 被说烂了，但很多人分不清它在禁止什么、没说什么。先把词用准，再谈选型。

前置是 [09 数据库](../09-database-systems/README.md) 里的事务和日志，以及 [08 网络](../08-computer-networks/README.md) 里「消息会丢、会重复、会迟到」。

## 建议顺序

1. **CAP** — 分区发生时，不能同时要强一致和完全可用。网络正常时这个三选二并不在束缚你。先记住这个适用条件，再听别人引用。
2. **一致性** — 强一致、顺序一致、最终一致，说的是副本之间的读者能看到什么。和数据库隔离级别不是同一个词，不要混用。
3. **复制** — 同一份数据放多份，为了扛挂和把读摊开。同步复制慢而稳，异步复制快但可能丢最近的写入。
4. **分片** — 数据按键拆到不同机器。要处理倾斜、再均衡，以及跨片查询变贵。
5. **Raft** — 一组机器选出领导者，用日志复制达成一致。先看懂选举和「日志只从领导者流出」，再看成员变更。
6. **分布式事务** — 一件事跨了多台机器。两阶段提交能原子地提交，但协调者一挂就会卡住。很多系统改用本地事务加补偿，或者把相关数据放在同一片里，避开它。

- 《数据密集型应用系统设计》后半本，和 6.5840 搭配

做 demo 时把网络延迟和丢包做成滑块。看领导者挂了以后选举要多久，看异步复制时从库读到旧值。
