终端、Shell、Git、编辑器、调试、正则。这是后面每一节的工作台。概念没学完也可以用，用得别扭再回来补。完整子类见 [知识地图](../knowledge-map.md)。

## 为什么要先学

demo 是跑在终端里的，动画页面是用编辑器改的，进度是用 Git 记的。工具不顺的时候，人会把时间耗在「命令打错了」上，误以为是概念没懂。MIT 的 [Missing Semester](https://missing.csail.mit.edu/)（[中文](https://missing-semester-cn.github.io/)）就是专门补这一块的，不讲某一门课，讲上课时默认你会的那些事。

做前端还会反复碰到：脚本起服务、看日志、在 CI 里读 diff、用正则处理一堆文件名。这些都落在这一层。

## 建议顺序

1. **终端** — 路径、相对路径和绝对路径、管道、重定向、退出码。知道上一条命令失败没有，比多记十个参数有用。
2. **Shell** — 变量、引号、简单脚本、自己的配置文件。先会改，再谈炫。
3. **Git** — 提交、分支、合并、变基、读 diff。能讲清「这一次提交改了什么」，再学历史改写。
4. **编辑器** — 选定一个，练跳转、多光标、工程内搜索。不要同时学三个编辑器。
5. **调试** — 日志打在哪、断点停在哪、怎么把范围二分到最小。先复现，再解释。
6. **正则** — 匹配、分组、贪婪。用来搜日志和改文本，不要一上来写不可读的一行。

## 书和课

- [MIT Missing Semester](https://missing.csail.mit.edu/)，中文译本 [missing-semester-cn](https://missing-semester-cn.github.io/)
- Git：[Pro Git](https://git-scm.com/book/zh/v2) 前三章够用很久
- 正则：先在自己的编辑器里对着真实日志试，需要时再查手册

做完这一节的标志：能自己把一个小 demo 跑起来，把输出重定向到文件，用 Git 留一次看得懂的提交。
