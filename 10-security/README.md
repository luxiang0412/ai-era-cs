# 10 安全

[← 回到路线](../README.md)

密码学基础、认证授权、Web 安全、系统安全、供应链。先问「保护什么、防谁」，再选机制。

## 为什么要学

前端和全栈站在攻击面的门口：表单、Cookie、依赖、CI。漏洞经常不是密码学不够新，而是把信任放错了地方。例如把密钥写进前端包，或者相信客户端传来的用户 ID。

## 建议顺序

1. **密码学基础** — 哈希、对称加密、非对称加密、签名。哈希不是加密。签名用来证明「谁发的」，加密用来保证「别人看不懂」。证书是把公钥和名字绑在一起，接到 [TLS](../06-network/README.md)。
2. **认证与授权** — 认证回答「你是谁」，授权回答「你能不能做这件事」。会话、Cookie、Token。先分清这两个词，再谈 OAuth 的流程。
3. **Web 安全** — XSS（把别人的脚本跑在你的页面里）、CSRF（拿着用户的浏览器去打你的接口）、注入（把数据当成了代码）、同源策略。每个都配一个最小的坏例子和对应的挡住方式。
4. **系统安全** — 权限、最小权限、缓冲区溢出的直觉：写越界盖掉了返回地址。不要求自己写利用，要求看到「为什么栈上的溢出危险」。
5. **供应链** — 依赖、锁文件、安装脚本、镜像来源。`npm install` 跑的是别人的代码。知道锁文件锁的是什么，以及更新时要看 diff。

## 书和课

- 密码学图像：《图解密码技术》够建立词汇。想再硬一点再看 Serious Cryptography
- Web：[OWASP Cheat Sheet](https://cheatsheetseries.owasp.org/) 当手册，不要当小说读。MDN 上同源和 Cookie 的文档写得具体
- 系统安全跟 [04](../04-system/README.md) 的内存布局一起看

练习用本地的故意写错的小页面，不要对别人的网站试。demo 可以是：一段没有转义的模板怎么把脚本插进去，加上转义之后同一段输入变成纯文本。
